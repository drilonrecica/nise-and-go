# ADR 0007: Repository Owner and Go Module Path

- **Status:** Accepted
- **Date:** 2026-08-27

## Context

The Go module path is a public contract. It appears in every `go install` instruction, in every application's `go.mod` that imports a Nise runtime package, and in the project recipe used by `nise doctor` and `nise upgrade`. Changing it after the first tag breaks every installation instruction and every generated application's imports.

The repository already lives at `github.com/drilonrecica/nise-and-go`, and Nise is a personal, maintainer-driven open-source project rather than an organization's ([GOVERNANCE.md](../../GOVERNANCE.md)).

## Decision

The GitHub owner is the maintainer's personal account, `drilonrecica`. The Go module path is:

```text
github.com/drilonrecica/nise-and-go
```

The CLI is installed as `github.com/drilonrecica/nise-and-go/cmd/nise`. Stable runtime packages live under `github.com/drilonrecica/nise-and-go/runtime/...`.

Explicitly excluded:

- A vanity import domain. It would add a hosted redirect that Nise must keep online for every application ever generated, contradicting the no-remote-service-dependency rule.
- A GitHub organization. Nothing in the governance model needs one, and creating one only to hold a name is not a reason.

## Consequences

- `go install`, Homebrew, documentation, and the project recipe can use one concrete path from the first commit of Go code.
- Applications generated by Nise import `github.com/drilonrecica/nise-and-go/runtime/...` directly. Moving the repository later requires a major-version-style migration for every application, even during `0.x`.
- GitHub repository redirects soften a rename for `git clone` but not for Go module resolution once the path is embedded in applications.
- Revisit only if the project moves to shared maintainership that genuinely requires organization ownership. That change would be a new ADR with a migration plan for generated applications.
