# `nise agents`

`nise agents` writes two static, Nise-owned artifacts into a generated
project for an external coding tool to read: `AGENTS.md`, a prose brief on
the project's stack, directory layout and ownership, build/test/lint
commands, and non-negotiable conventions; and `.nise/architecture.json`, a
versioned, machine-readable description of the same layout plus the
project's selected modules.

It is a **static artifact generator**. It performs no network request,
invokes no external tool, and contains no AI or model-provider code
(`privateDocs/DECISIONS.md`'s AI section). Both outputs are derived
entirely from the project's recipe (`nise.json`) and this build's own
compiled-in knowledge of
[Generated application layout](../generated-application-layout.md).

```
$ nise agents
$ nise agents --force
$ nise agents --json
```

See [CLI output contract](../cli-output.md) for `--json`, `--verbose`,
`--quiet`, and the exit-code contract in general.

## Where it looks, and where it writes

`nise agents` looks for `nise.json` in the current directory or any
parent — the same project-root convention `internal/recipe` and
`nise doctor` use — and writes both outputs at that project's root:
`AGENTS.md` beside `nise.json`, and `.nise/architecture.json` under a
dot-prefixed directory (the same idiom as `.git/`) reserved for
tool-readable metadata that isn't part of the application's own
documented tree.

## Determinism

The same `nise.json` always produces byte-identical output, from any
machine, in any directory: nothing in either file is a timestamp,
hostname, username, or absolute path. Running `nise agents` twice against
two directories seeded with the same recipe produces files that `diff`
reports as identical.

## Ownership and refusing to overwrite a hand edit

Both files are Nise-owned: they carry the `Code generated by nise; DO NOT
EDIT.` header (a JSON `generated` field, for `architecture.json`, since
JSON has no comment syntax) and are meant to be regenerated, never
hand-edited.

Each file also embeds a content hash of its own generated body — computed
at generation time and stored in the file itself, rather than in a
separate sidecar that could go missing or fall out of sync independently
of the file it was meant to protect. Before overwriting either file,
`nise agents` recomputes that hash from the file's current on-disk content
and compares it against what the file itself declares:

- If the file does not exist yet, there is nothing to lose; it is written.
- If it exists and still matches its own embedded hash, it is exactly
  what `nise agents` last wrote, and is safely regenerated.
- If it exists and no longer matches — a human edited it, or it was
  replaced by something that never came from `nise agents` — the command
  refuses to overwrite it.

A refusal shows the conflicting file's current content (truncated to 20
lines / 2000 characters) before the error, in both modes: as informational
output on stdout in human mode, and as the JSON error envelope's
`details` field in `--json` mode (JSON mode has no channel for
informational prose — see [CLI output contract](../cli-output.md#json-mode-json)
— so the same preview travels through `details` there instead). Refusing
one file refuses the whole command: neither file is written, so
`AGENTS.md` and `architecture.json` never drift out of sync with each
other because one half of a run was blocked and the other was not.

```
$ nise agents
--- /path/to/project/AGENTS.md (current content that would be lost) ---
... your hand-edited content ...
1 generated file(s) would be overwritten but do not match nise's last generated content
Re-run with --force to overwrite, discarding the hand-edited content shown below.
```

### `--force`

Pass `--force` to overwrite both files unconditionally, skipping the
verification check entirely. There is no partial-force: `--force` always
regenerates both files together.

## Exit codes

| Situation | Exit code |
|---|---|
| Both files written (first time, or an unedited regeneration) | `0` |
| No `nise.json` found in the current directory or any parent | `3` (`ExitPrecondition`) |
| `nise.json` exists but does not parse | `3` (`ExitPrecondition`) |
| One or more generated files would be overwritten but do not verify, and `--force` was not given | `1` (`ExitError`) |
| A filesystem error (for example, an unwritable directory) | `1` (`ExitError`) |

## `architecture.json` schema

`.nise/architecture.json` declares its own schema version in a
`schemaVersion` field (currently `1`) so a consumer can tell which shape
it is reading without depending on `nise`'s own version. Its top-level
fields:

| Field | Type | Meaning |
|---|---|---|
| `schemaVersion` | number | The schema version this document was written under. |
| `generated` | string | Always `"Code generated by nise; DO NOT EDIT."` — the ownership marker, as a field rather than a comment. |
| `contentHash` | string | `"sha256:"` followed by the hex digest of this document with `contentHash` itself set to `""`. Used by `nise agents` to detect a hand edit; not meaningful to any other consumer. |
| `profile` | string | The recipe's generation profile. |
| `modules` | array | Every compile-time module this build of `nise` knows about, each with `name` and `selected`. |
| `directories` | array | The generated tree's directories, each with `path`, `ownership` (`"nise"` or `"app"`), and a one-line `description`. Mirrors [Generated application layout](../generated-application-layout.md)'s Tree section; does not enumerate every file — a directory named `store/`, `openapigen/`, or `embedded/`, or a file ending `.gen.go`, is always Nise-owned wherever it appears, and that rule is stated once rather than repeated per file. |
| `features` | array | The project's vertical-slice features under `internal/features/`, each with `name` and `path`. Empty until a feature exists — Slice 1 leaves `internal/features/` holding only a `.gitkeep` — and is never omitted, so a consumer can always read its length without a presence check. |

A future schema change that alters an existing field's meaning or
presence bumps `schemaVersion`; a purely additive optional field does not.

## Safety notes

- No network request, ever: every input is a local `nise.json` and this
  build's own compiled-in content; every output is a local file write.
- No secret can appear in either output: neither file's content is built
  from anything but the recipe's own non-secret fields (schema version,
  profile, module selection, and the two version strings it records).
