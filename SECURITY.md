# Security Policy

## Current status

Nise & Go is currently pre-alpha and has no supported production release. Until a supported version is published, the repository is design and development work, not a security-reviewed framework.

## Reporting a vulnerability

Use GitHub's private vulnerability-reporting or Security Advisory flow for this repository. Do not open a public issue containing exploitable details, credentials, private data, or a working proof of concept.

Include, where possible:

- Affected version or commit.
- A concise description of the impact.
- Reproduction steps or a minimal proof of concept.
- Required configuration and preconditions.
- Suggested mitigation, if known.

Do not test against systems you do not own or have explicit permission to test.

## Response expectations

This project has no response-time, disclosure-time, or fix-time SLA. Reports will be evaluated as maintainer availability permits. Publishing details before a fix is available may put users at risk; coordinate disclosure when practical.

## Supported versions

| Version | Supported |
|---|---|
| Unreleased development code | No production support |

This table will be updated when the first supported release exists.

## Security claims

“Security-first” describes the design priority. It does not mean the project is vulnerability-free, audited, or suitable for a particular threat model. Operators remain responsible for deployment, secrets, database security, patching, backups, access control, and monitoring.
